## Fixed

### B1 Reminder after a delay in the portal (spec 0.63, REQ-TMR-009)
- The portal API accepts `seconds` for kind `reminder` (a countdown, works with the clock unset) as well as `date` and `time` (needs the clock). Giving both is refused. Editing can switch between the two. Each item now carries `countdown: true/false`.
- The reminder dialog has an "After a delay / At a time" choice, reusing the timer's amount-and-unit fields. `ui.html` was rebuilt and `openapi.yaml` updated.
- Tests: two Rust tests (both seen failing against the old behaviour), one portal unit test (not run against the old code), one browser flow; browser tests 39/39.

### U1 Drift check for the coding-agent snippet (spec 0.63)
- A portal unit test reads `crates/core/adapters/claude-code.json`, fills the placeholders and compares the hook JSON and bridge line with what the page builds. **Only the drift test was done**, not serving the lines from the API (see "Left open").
- The earlier hook failure was most likely `portal/lint/node_modules` being missing (`npm run lint` dies with MODULE_NOT_FOUND until `npm ci` is run in `portal/lint`), not the test itself. This is inferred; the original output was lost.

### B2 The stop-while-working listening window (spec 0.64, REQ-VOI-025)
- Decision: the 4-second window is now `min(no_speech_ms, 4000)`, so a device that tunes `no_speech_ms` down tunes this too. The follow-up window stays its own setting (`follow_up_secs`). `configuration.md` says which setting controls which window.
- Test seen failing against the old constant.

### B3 IPv6 link-local counts as private (spec 0.64, REQ-SEC-001)
- `fe80::/10` is now private in `netpolicy::is_private_ip`. Test seen failing first. The effect is smaller than the open list said: see "Found while fixing".

### B4 Hive peer address (spec 0.64, REQ-CFG-009)
- Decision: a peer is accepted from any private source and listed under the packet's **source** address; an advertised A record is ignored and no longer drops the peer. The private-source filter stays. Still not checked, and stated in `docs/guides/hive.md`: the interface, multicast versus unicast, and the TTL.
- The test was rewritten; it was not run against the old code.

### B5 One rule for held actions (spec 0.62, REQ-SEC-011)
- Decision: **a call that needs no hold always runs, including after a hold in the same batch, in a normal turn, an event turn and a realtime session.** A call that would itself need holding is refused ("an action is already waiting"). The held action stays until the user answers or its window ends. A second `ask_user` after a hold is still skipped.
- The fixer let **reversible** calls run after a hold as well as read-only ones, because the realtime path already did. This is looser than the old normal-turn rule; see "Decisions".
- Tests: four new, all seen failing first. Two existing tests and two evaluation scenarios were changed because they encoded the old skip rule. In the scenarios the asserted audit decision changed from `blocked:pending` to `blocked:invalid` for the destructive tool `docker__remove` (the gate now judges it before looking at the pending action); the scripted model replies were not changed.

### B6 `ask_user` not offered in outside-started turns (spec 0.62, REQ-SEC-012)
- `pseudo_tools` leaves `ask_user` out when the turn was not started by the user. The refusal in the gate stays as the backstop. Test seen failing first.

### B7 Password reset for ESPHome devices (spec 0003 0.3.4, REQ-SAT-020)

REQ-SAT-020 now says the long-press reset is for the native satellite protocol only; a device reached through ESPHome resets the password with `clawdot --reset-admin` on the core's machine. `esphome-satellite.md` and `forgot-password.md` say so, and the text `--reset-admin` prints was corrected.

### B8 Terminal shows the line actually spoken (spec 0.64, REQ-TMR-015)

### B9 Warn about retired configuration keys (spec 0.64, REQ-CFG-038)

### B10 Stable endpoint ids (spec 0.65, REQ-INB-008, REQ-CFG-028)
- Each endpoint has a random 128-bit id made at creation. Events, queued replies, held questions, rate-limit state, coalescing and eviction are keyed by it. The name stays what URLs, the portal, `--endpoint` and the spoken origin use, and the bridge's wire format is unchanged (the protocol stability test passes unmodified).
- Deleting an endpoint now also ends a question it was asking (it did not before).
- **Migration:** at start, an endpoint without an id gets one and the endpoint file is written first, before anything else, and start-up fails if that write fails (an id that was not saved would orphan data at the next restart). Saved events and replies that carry only a name are tied to the live endpoint of that name, or dropped if there is none.
- Tests: eight failed against a model of the old behaviour. Migration was tested only on files the fixer wrote and then stripped of the new fields, not on a real old install.

### B11 Stopwatch on the monotonic clock (spec 0.61, REQ-TMR-011, REQ-TMR-012)
- While the program runs the stopwatch counts on the monotonic clock, so network time arriving cannot add to it or take from it. It is saved as seconds counted plus the wall time of the save; at load the time the program was off is added only when the wall clock is valid now, was valid at the save, and is not behind it. Otherwise nothing is added, and never a negative amount (the rule countdowns use).
- The "clock went backwards" refusal is gone. Old files (`started_at`, `last`) still load, and a test loads the old shape. Starting, lap, stop and read still need a set clock; reset does not.
- Tests cover a forward and a backward jump, a restart with a valid clock, a restart behind the save, and the old file shape; they were not run against the old API.

### B12 Update file named from the build target (spec 0.64, REQ-UPD-004)
- Decision: the release file is named from the target the program was built for, so an ARMv6 build looks for `clawdot-linux-armv6` (no release carries it, so the portal says it has no signed file for the device) instead of being offered the `armv7` one.
- **Corrected after the fixer's version.** It detected ARMv7 with `cfg!(target_feature = "v7")`. I checked: stable Rust reports no `v7` feature for `armv7-unknown-linux-musleabihf` or any other ARM target, so the Dot would have been named `armv6` and could never have updated. The build script now records the target triple (`CLAWDOT_BUILD_TARGET`) and the name is taken from that. Tested with a table of triples and a check that the build script's value is present. Not yet confirmed by an actual armv7 cross-build (CI's cross job is still a TODO).

### Review round: three reviewers read the code nobody had read, and the findings were fixed (spec 0.67; satellite protocol 0.3.5; device contract 0.6; wake word 0.3)

Three read-only reviewers went through the device daemon, the wake-word and reference-satellite crates, the unread parts of the core, and the portal. #### Core (C1 to C17)
- **C6, the daily counters and an unset clock (the most serious).** The day was taken from the clock even when the clock was not set, and the counters rolled whenever the day *changed*. On a device with no battery clock each boot started in 1970 (wiping today's spend and action counts) and rolled again when network time arrived. Now `Assistant::local_day()` is 0 while the wall clock is not valid, day 0 or a lower day never rolls the counters, and only a greater real day does; spend counted before the first real day stays on it. Same rule in `audit.rs` `load_counts` and its counters file. Tests seen failing first for the spend; the audit tests were not run against the old code.
- **C1, a cut-off answer is not free.** A request that fails after the provider began answering (a stream that dies, a response over 1 MiB, a malformed line) was counted as costing nothing. New `LlmError::Interrupted`; the prompt is priced for it, both on the turn path (the gate call site, with a test that fails without the change) and in the speaker task. A refusal before any answer stays free.
- **C5.** The reported-cost path rounded; it now rounds up like the others.
- **C2, C9, C10 (audit).** `api_key: abc123`, `passphrase: x` and `pin: 1234` are redacted; a long mixed-case or all-capitals path segment in a URL (a Slack-style webhook secret) is redacted; `#access_token=` fragments are handled like a query. A lone `key:`, `session:`, `auth:` and similar are exempt so ordinary sentences are not refused as notes. Argument keys that clean to the same name get `_2`, `_3`, so the log cannot record a decoy under a real key. A failed write no longer merges two records. Not run against the old code.
- **C4.** When a satellite goes away its running turn is cancelled (it kept spending on a model call for a speaker that was gone). Test seen failing first.
- **C7, C3.** A stream that ends before `[DONE]` and before any finish reason is now an error, and a finish reason of `length` with tool calls is invalid. Streamed tool calls without an `index` no longer merge into one, and repeated provider ids are suffixed.
- **C8, C14, C13.** A random-source failure refuses the satellite connection instead of giving every speaker the id of zeros; an identity file with an empty key is damaged, not a new identity; expired hive peers are purged when a new one arrives and the fallback peer name is cleaned.
- **C16, C11.** Writes to the realtime service have a 5-second timeout and end the session on timeout; a speech start whose transcript never arrives counts as heard after 8 seconds, so the user's "yes" cannot be blocked until the held action expires.
- **C15, C12, C17.** Hand-edited notes are tidied and given unique ids; the realtime guide says the counted spend is audio only; one comment corrected.

## Decisions made on your behalf

Confirm or reverse. The first four were in the previous list; the rest are new.

1. A rung timer or reminder with no speaker connected waits, and after 5 minutes is announced as missed (REQ-TMR-015).
2. A reminder after a delay is a countdown and works before the clock is set (REQ-TMR-009).
3. Printed set-up addresses use the machine's name with `.local` (REQ-CFG-016).
4. A held confirmation stays until the person answers or its window ends (REQ-SEC-011).
5. B5: after a hold, reads **and reversible calls** still run in the same batch; only another call that needs holding is refused. If you want it stricter (only read-only calls run after a hold), say so.
6. B4: a hive peer whose advertised address differs from where the packet came from is accepted, under the source address.
7. B7: ESPHome devices reset the password with `clawdot --reset-admin`; there is no on-device route.
8. B2: the stop-while-working window follows the tuned value, up to 4 seconds.
9. B10: handled (closed) events of endpoints that no longer exist are dropped on the first start after upgrade.
10. **C6:** the daily counters never roll backwards or while the clock is unset. The cost: a clock wrongly set far into the future and later corrected leaves the counters on the future day until real time catches up, so the spend cap would stay reached. It fails safe. Say if you would rather allow a large backwards step to roll.
11. **C11:** a speech start with no transcript counts as heard after 8 seconds (the value is the fixer's; the code had no transcript wait).
12. **C16:** writes to the realtime service time out after 5 seconds.
13. **D12:** the audio-device options refuse empty, option-looking and control-character values but do not use the strict token check, which would reject names such as `Microphone (USB Audio)` that ffmpeg on Windows needs.
14. **D2, D3:** announcement deferral in quiet hours is not applied on a device and several board fields are not used by the daemon; both are documented as partly met, not fixed (see the open list).
